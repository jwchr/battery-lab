# Battery Lab

## Review guidelines
When you review a plan, branch or pull request here, check it first against the rules in `CLAUDE.md` and cite the rule: Ring Bluetooth connects only when the user starts something that needs it (never on a background schedule; listening for broadcasts is fine), nothing identifying in commits, issues or PRs (no serials, Bluetooth addresses, device names or raw readings), no accessibility services, and nothing that touches Samsung's apps. Then check what loses or corrupts the battery history: a database migration or write interrupted partway, a backup that misses a table or the `-wal` file, a restore over newer data, a monitored or A/B test left open across a reboot or app kill, a Bluetooth link not closed on every path, and anything that would need an uninstall or a differently signed build. Then ask whether the change keeps the app easy to use and fits what's already there (no duplicate features, no needless settings, plain words, and a full feature spread across clear steps, screens or buttons so no single screen is overwhelming; simple never means cutting the feature), and whether it looks good (clean, even spacing, the same look as the rest of the app, nothing cramped, checked on the real screen); this is Jeff's "Keep every app simple" rule in `~/.claude/CLAUDE.md` (Nov 24, 2026; reason: an app crowded with duplicate features and confusing screens stops working well, and an app that looks nice is one he keeps using; Jeff added the same day that features are not to be dumbed down, only presented so they are not overwhelming). Rank findings P1 to P3 with file:line and a concrete trigger. Skip style.
